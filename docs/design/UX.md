# Interface specification

The authoritative specification for application screens, transitions, and UI states. Implementation and verification status are recorded in [ROADMAP](../../ROADMAP.md). Product rules are owned by the [product specification](../product/overview.md); API/data and client authentication behavior by the [architecture](../architecture/overview.md); job states by the [sync workflow](../architecture/sync-workflow.md).

The [visual reference](DESIGN.md) supplies the appearance of these screens. Read it together with the token/CSS assets under the shared [frontend design inputs](../stages/README.md#frontend-design-inputs), which define their roles and precedence. Reference examples are translated into the application's own screens and copy. Complete dated execution/report history remains unavailable through the current public API.

## Transitions and application shell

Login/registration → OTP → Connections → Project catalog → Project/synchronization → Snapshot tasks → Self-review. React Router in Declarative mode supplies navigation and a protected layout; direct entry and reload follow [frontend routing](../architecture/overview.md#frontend-routing).

The protected application shell has exactly Connections and Projects as primary navigation. Projects stays active for project/snapshot deep links. Use a 240px expanded desktop sidebar with the existing offcanvas collapse mechanism; collapsed navigation is inert. Below 768px use the existing Sheet-based mobile navigation, closing it after navigation and restoring focus to the toggle in the current shell, even when navigation unmounts the previous one. Keep the product identity, signed-in application account/email and Sign out discoverable. Account and session help is a keyboard-accessible disclosure containing the existing access-token expiry/renewal guidance and the fact that accepted background work continues after sign-out. The application account remains distinct from the tracker token owner.

A shared PageHeader provides one wrapping page heading, description and optional named action group. A compact shell indicator explains offline (synthetic data/scripted model), demo (synthetic data/live model), or live (trackers enabled/live model) from the authenticated runtime mode. It is not a live connection-health indicator or an assertion about an individual saved historical resource.

Page padding sits outside the content ceiling: 16px mobile, 24px tablet, 32px desktop; vertical padding is 24px mobile and 32px from tablet upward. Pages choose Connections (1040px), Projects (1200px), workspace (1280px), reading (760px), or full available width. Authentication retains its separate 440px layout. Saved reports use the reading ceiling within the Self-review tab of the project workspace. Preserve one main landmark and a keyboard skip link that focuses it. Wide tables scroll within a labeled region; long titles/account labels wrap without main-page overflow. Widths are maximum content widths, not minimum viewport sizes.

Stack workspace columns and catalog controls according to the content width remaining beside navigation, following [DESIGN's responsive adaptations](DESIGN.md#layout-and-responsive-behavior). Project sections remain reachable through a labeled horizontal tab region and Radix arrow-key navigation on narrow screens. Long identifiers wrap in table cells and Sheet headings. On short screens, navigation and account help remain accessible through scrolling; task/evidence headers and bodies scroll independently. Wrapping action labels retain the full action name and shared touch target.

Compose screens from the selected shadcn/ui components and shared theme rather than separate per-screen visual systems. TanStack Query supplies saved server-data states; forms, selection, and dialogs use local React state. Loading and account isolation follow [frontend data flow](../architecture/overview.md#frontend-data-flow).

## Login and OTP

Provide email/password forms for login and registration in one focused AuthPanel with separate product identity, title/purpose and a divided footer for switching between forms. The next action explicitly sends a verification code; explain that signup creates the account only after verification and login grants full access only after OTP. Keep native validation and field-associated errors, mark invalid credentials without guessing which credential is wrong, and focus the first invalid field. Switching login/registration clears the previous form's ephemeral values and feedback while retaining the authorized return target. Preserve current-password/new-password autofill and password managers. Authentication rules and lifetimes remain in [D04](../decisions/D04-auth-and-credentials.md).

After the first step succeeds, group the masked destination, local-time expiry with timezone and mail hint above one six-digit code input. Keep numeric keyboard, one-time-code autofill and paste; no segmented inputs or automatic submission. Verification and resend have separate pending labels and disable duplicate submissions. Associate wrong-code errors with the input; show safe verification and resend errors beside their actions without treating infrastructure failures as invalid input. A successful resend clears the old code, focuses code entry and announces success separately from errors. The rate-limit countdown is outside live regions. Show expiry/attempt-limit messages and a visible restart link in the footer; restarting returns to email/password and retains the authorized return target. Never display secrets in feedback.

When Mailpit is the configured destination, show an Open email in Mailpit link to localhost:8025. With external SMTP, direct the user to their email inbox. This hint follows mail configuration rather than APP_MODE. The user reads and enters the code; no automatic filling or code in the API response is implied. After OTP, return to the last authorized internal page. Offline uses the same login flow with a clearly labeled model mode.

Successful access-token renewal keeps the user on the current screen. A definitive refresh rejection returns to password + OTP while saved runs/reports remain in the database. Infrastructure errors show a retryable state. Logout and account changes clear cached views and close local streams across tabs; detailed recovery/coordination is owned by the architecture.

## Connections

After the heading, show equivalent quiet Connect Linear, Connect ClickUp and Connect Jira Cloud actions from the loaded availableProviders response. Occupied slots show Manage instead of another create action. Show loading before availability is known and a read-retry action on failure. In demo/offline modes, offer only the available Add demo source action (Manage demo source once saved), with synthetic data and the actual scripted/live model label. Slot limits remain owned by the [product scope](../product/overview.md#scope).

Connected accounts use divided rows showing provider, connection name, stored status, verified tracker owner and last verification date in UTC. Explain that verification records a past check rather than current tracker health. Preserve Jira link-availability warnings on the row. Manage expands secondary details: full verified user ID, source/model modes, identity/site restrictions, Browse projects, Replace credentials and Delete local connection. The application login and verified tracker identity remain distinct.

Connect and replacement use focused Dialogs with the shared [visual treatment](DESIGN.md#layout-and-responsive-behavior). Forms contain a name and password token input; Jira additionally requires the Atlassian email, UUID cloudId, scoped-token help and official lookup/token links. Replacement shows the saved name read-only and submits credentials only. Native validation focuses invalid inputs; errors retain nonsecret values. Clear the token on submission and unmount the form on Cancel/Escape/close; no stored secret is redisplayed. Pending submissions disable duplicate writes but can be dismissed with an explicit notice that the request continues. Page-level mutation ownership reconciles completion and provider-slot conflicts even after dismissal. Success closes the form, announces the saved result and restores the trigger; a stable account-list heading is the fallback when an opener no longer exists. New verification errors do not change a saved row's status.

Deletion uses AlertDialog with initial focus on Cancel and the explicit permanent loss of local projects, snapshots, tasks, reports and credentials; the tracker token and remote projects remain intact. Keep safe server errors in the open dialog, including active-job conflicts, and allow another explicit attempt. Do not infer connection-wide idleness from this view or disable legal same-identity replacement during background jobs. Identity/scope replacement and deletion rules remain owned by [D04](../decisions/D04-auth-and-credentials.md#tracker-connections).

## Project catalog

Use the Projects content ceiling and one semantic table with Provider, ID, Name, Workspace / Location and Actions columns. Provider comes from the connection; ID is the remote externalId, and the name links to the existing local project route. Location shows the saved breadcrumb and connection display name. ClickUp resources have an explicit List label; fixture resources say Synthetic demo source. Matching names or remote IDs from separate connections remain separate entries. Long IDs can be expanded with keyboard or touch to reveal/select/copy their full value; long names and locations wrap. The table scrolls within its labeled, keyboard-focusable region without hiding essential columns. The named arrow action opens the same local project; no whole-row click or unsupported project deletion is introduced.

Label the text field Search loaded projects. Apply trimmed, case-insensitive matching to name, external ID, breadcrumb/location and connection name. The All providers / Linear / ClickUp / Jira Cloud filter affects displayed rows; synthetic resources remain under All providers. Show N matches in M loaded projects, where M is all currently loaded resources. A zero match describes loaded results, not the existence of remote projects. Clearing or changing filters retains fetched pages and independent discovery.

Each connection retains its own paginated query, successful pages, local-ID deduplication, cursor-loop protection and continuation/retry controls. Below the merged table, Catalog discovery identifies each connection, loaded count and complete/loading/more-available/error/loop state. A failed continuation leaves successful rows usable, retries that connection's continuation, and does not hide other catalogs. A loop stops continuation, remains visibly incomplete and offers a catalog read retry. Until every relevant connection ends successfully, show More projects may be available. Load remaining pages to broaden this search. Do not run an automatic load-all loop or claim global search. Distinguish initial loading, empty completed discovery, missing connections, no matches and safe provider/credential errors. Selecting a resource opens its local project page, which shows the confirmed tracker token owner as the future review subject.

## Project page and synchronization

Keep `/projects/:id` and the existing `?snapshot=` parameter. Project-local Radix tabs provide Overview, Tasks, Self-review and Activity; Overview is the initial tab after reload. Tabs are local view state with no additional URL convention. The shared controller owns all queries, active-run discovery, subscriptions, accepted commands and idempotency keys above the panels. Tab changes never submit commands or stop recovery.

The persistent project context shows provider/resource, connection, verified tracker owner, selected snapshot and its saved inclusive UTC period. Keep source IDs secondary. The selector retains latest-successful and paginated historical attempts; an explicit inaccessible snapshot or snapshot from another project is an error, never replaced silently. The existing project-scoped saved-task read verifies the project/run pair before metadata is displayed. Preserve unrelated query parameters. Snapshot changes reset task selection, cursor, partial acknowledgment and stale detail/confirmation panels; project/account/session changes reset local workspace state. Selected-refresh periods resolve through validated owned base-job reads, with cycle/lookup bounds and cancellation. Missing or invalid context is visible and cannot confirm an ambiguous refresh.

Overview uses flat sections and a supporting facts column: saved tasks, review-eligible tasks only when available from a review, actual coverage and report availability. Sync targetTasks is the saved set, not the owner subset. A saved report's pointer belongs to the selected snapshot. Do not claim a complete report history or a last-sync timestamp from the recent-run preview.

Without a snapshot, expand the period form. Afterwards offer a visible Synchronize again control. Native dates are inclusive and labeled UTC; editing them does not relabel saved evidence. Create self-review after synchronization is initially unchecked. Explain the [product selection rules](../product/overview.md#selection-rules): all statuses/assignees, task creation dates, current source data rather than a historical work log; synchronization includes model analysis even without an automatic review. Overview emphasizes the next meaningful action: synchronize, inspect partial evidence, create a review or view the existing report. Conflicting execution is disabled with background-work context; viewing saved content remains possible.

A persistent job strip separates execution from connectivity. Show actual queued/running/result state and map listing/reading/analyzing/reducing to readable stage labels. Unknown stages say Processing with the saved stage in details; finished uses the persisted outcome. There is no separate observable Saving milestone or ETA. Saved/processed-detail counters are explicit and omit unknown totals. Processed details include retained records during selected refresh and do not count new tracker requests. Completed units across levels and created leaf batches remain separate counts, never a fraction. Announce state/stage changes rather than every counter update. Activity retains paginated sync history and a clearly labeled up-to-20 recent-execution subset. Inspecting a recent execution focuses its details without changing the selected snapshot. Show the inspected execution’s actual coverage, durable warnings, copyable IDs and saved selection; review discovery/import flags are explicitly inherited. Processing units and safe traces load only when their disclosures open, retain successful pages on retryable read failures and use server continuation cursors to reach later units. Human event labels and actual exposed event timestamps are primary; unknown safe event fields remain in secondary disclosures. Do not infer execution start/finish dates from trace events. Sync history read retry and continuation are separate from starting another execution.

On stream loss, retain the saved execution state and show Reconnecting / Updates interrupted; background work may still be running and recover persisted state through GET/reconnect under the [SSE policy](../architecture/sync-workflow.md#sse). A missing/inaccessible run ends reconnect with its safe error; exhausted transient recovery offers Reconnect while the background job continues. Accepted work continues after closing the tab or logging out. On terminal sync, update the task list and show the saved outcome. The persistent job heading provides the polite stage/completion announcement; durable outcome warnings/errors do not repeat it. Offer View saved tasks or View self-review as a quiet explicit action that selects the result’s source snapshot and section. Loading the saved review result resolves its actual source snapshot; do not derive that relationship from the currently selected snapshot. Keep the last observed automatic child available after it leaves the active-run preview, and never switch tabs or move focus on background completion. When automatic review was requested, continue with Tasks saved; preparing self-review and show its separate outcome. A review failure leaves the saved sync available. Skipped auto-review has a visible reason.

Distinguish succeeded, partial, and failed using the [state rules](../architecture/sync-workflow.md#states). Show missing required coverage separately from expected excerpt/comment limits. Partial runs remain selectable with a banner; failed/partial runs do not silently replace the previous successful snapshot. Retry is an explicit new run that can make new paid requests; duplicate clicks on the same command remain protected by server idempotency.

## Snapshot tasks and selected refresh

The Tasks tab retains the selected snapshot and resolved UTC period in the workspace header. Use a horizontally scrollable semantic table with separate selection, identifier/title, provider status, assignees, creation date, saved evidence and source-action columns. Dates use readable UTC labels; exact saved retrieval time remains in task details. Fresh/Copied/Stale describe retrieval provenance rather than current tracker accuracy. Only the verified connection owner's known ID may use its trusted name; other assignee IDs remain readable. Source actions use saved safe URLs and accessible task-specific names.

Selection belongs to internal task-snapshot IDs and stays in the page controller across pagination and tab changes. The contextual toolbar shows the complete selected count, including off-page tasks, Clear selection and Refresh selected (N). Do not infer select-all semantics. Changing snapshot/project/account/session or accepting a command clears selection as defined by the controller. Preserve saved-task pagination, loading, empty/error states and read-only retry; display a precise current-page range rather than an invented complete filtered total.

Refresh selected opens a compact Radix Dialog with selected count, resolved inherited UTC period, base snapshot and model-usage consequences. Its optional automatic-review checkbox resets unchecked whenever opened. Cancel receives initial focus. Missing/invalid base context blocks confirmation and offers read recovery. Only explicit confirmation submits the existing tasks-mode command; pending and conflicting work disables another start. Dismissing the dialog does not cancel accepted work; outcome feedback remains at page level. On close, restore the opener or the stable table/tab fallback if accepting the command removed its trigger.

Refresh creates a new snapshot containing refreshed selected tasks and copies of the others. Copied or stale records keep their original retrieval times; a failed refresh can retain a stale copy without changing the base. Review covers the qualifying subject's tasks across the resulting snapshot; a full period sync discovers additional tasks. Detailed semantics remain in the [sync workflow](../architecture/sync-workflow.md#full-sync-and-selected-tasks).

Task details use one 640px maximum-width Sheet, full viewport width on mobile, with an independently scrolling body. Its header shows identifier/title, retrieval context and the saved verified source action. Content follows provenance/availability warnings, description, saved comments, findings and source metadata. Distinguish unavailable/pending details from an available empty description, unread comments from successful empty reads, and failed/limited reads from complete saved content. Retained/copied evidence uses its actual original dates; no author/read-error/source-navigation fields are invented beyond the public contract.

Finding citations and source-registry actions switch this same Sheet to saved evidence, with Back to task and predictable focus return. Show the exact claim quotation and matching saved source excerpt, dates, truncation and safe registry link. An unavailable/mismatched source remains an explicit internal-evidence error; never fetch external text to fill it. Escape/Close dismisses the Sheet and restores its task opener or the stable workspace fallback. These saved-data views initiate no tracker/model work.

## Self-review

Show the confirmed token-owner subject, period, and source snapshot. The Review button creates a report or regenerates the current one through the shared review process. The previous valid report stays available while generation runs and remains current if generation fails. Repeated active-run actions are disabled in the UI and checked by the server.

Review of partial data requires explicit acknowledgment of incomplete coverage; failed snapshots are unavailable for review. A report from a partial source retains its partial label and inherited warnings. Show the selected snapshot’s own current report. Other snapshots and their reports remain accessible through the selector; a previous-snapshot fallback may appear only after its actual pointer has been resolved and labeled Based on the previous snapshot. [D05](../decisions/D05-sync-review-and-refresh.md) owns versioning behavior.

Present the saved report as a 760px reading column with a document header: project, saved review subject, UTC creation-date period, generated time and latest-successful/historical/partial snapshot context. Use full copyable identifiers in provenance rather than inventing a report version. Group claims into the saved work areas and retain the exact categories Task description, Reported result, and Measurement from a source. Keep limitations and the saved explanation visible. Use cautious source-based wording under the [interpretation rules](../product/overview.md#result-interpretation). Surface later information, unknown timing, missing evidence, and qualifications about individual contribution or rollout.

Number citations by exact source ID and quote pair across the report. A citation opens the saved source and exact quotation in the existing 640px/full-mobile evidence Sheet, including source dates, truncation, snapshot provenance and its verified external link when available. A null link leaves internal evidence available; an absent registry entry is an explicit error. Back to self-review and Escape restore citation focus without moving the document. Render source/report text as escaped text. Only a report matching the selected source snapshot and current report pointer is displayed; snapshot/report changes close stale evidence.

Place Markdown/JSON downloads in the document header and the explicit regeneration action in a separate disclosure below the saved report. Keep partial coverage above the document. Empty reports preserve their explanation, limitations and exports while distinguishing zero saved tasks, zero qualifying subject tasks and no supported claims from generation failure. Model usage, provenance and safe trace are secondary disclosures. Validate the unknown usage payload before presenting token totals, attempts and the backend estimate; label incomplete subtotals and Scripted model explicitly. Synchronization usage is separate. Fetch the paginated saved trace only when opened; unsupported usage shapes retain safe raw JSON.

Download Markdown/JSON from the saved report. Opening and exporting saved results do not call the model. Display actual usage separately from estimated cost; unknown/scripted usage remains visibly unknown. New generation is an explicit action. Empty evidence or no qualifying tasks produces an explanatory empty state, rather than an invented achievement.

## Shared states and accessibility

Loading, empty, validation, forbidden/not found, infrastructure error, partial coverage, and expired authentication are distinct. Shared ErrorState, EmptyState and LoadingState compositions keep the missing resource, safe failure and relevant recovery action explicit. Reserve initial content space with static skeletons; subsequent reads use compact inline loading. Read failures retain validated content only for retryable transport/infrastructure errors; definitive inaccessible responses hide that resource’s cached content. Error recovery is labeled as a saved-data read, reconnect restores progress, and a new paid execution remains an explicit domain action. Shared feedback uses explicit information/loading/success/warning/error variants: inline pending/success, a visible coverage warning, and a strongly bounded blocking error with its recovery action. Nonblocking updates use polite announcements; blocking errors use assertive announcements. Do not infer states from message text. OTP resend success is success feedback, separate from rejected/expired-code errors; resend and verification timing/security rules are unchanged. During renewal, keep the current page in a pending state rather than flashing the login form. Only definitive authentication failure returns to login; infrastructure failure preserves a retry path. Show safe messages and a request/run identifier where useful, without raw provider errors or keys.

Target WCAG 2.2 AA: normal text contrast of at least 4.5:1, large text 3:1 and meaningful control/focus boundaries 3:1, with adequate target spacing and zoom/reflow. These are acceptance targets rather than a conformance claim. Provide explicit labels, keyboard operation, visible focus, dialog focus management and aria-live for relevant status/error changes. Pair status color with text or icons. Icon actions have context-specific accessible names; decorative icons are hidden from assistive technology. Use native table headers/captions and labeled, keyboard-focusable scroll regions. Essential controls must be available without hover.

At 200% zoom, content and actions remain accessible. Respect reduced-motion preferences; progress has no decorative looping animation or fake timed advancement. Announce stage/terminal/error changes rather than every counter tick; OTP resend countdown is not a continuously announced live region. Preserve native input semantics, paste, password-manager autofill and readable autofill colors. Confirm responsive navigation, usable forms with the mobile keyboard, and accessible table overflow. Review composed shadcn/ui controls after applying the theme.

Render model/tracker content as escaped text with verified registry links. Keep focus predictable after explicit actions; announce background completion without an intrusive modal. The manual verification journey is in [S06](../stages/S06-submission.md); technical authentication/cache/SSE behavior stays in the architecture and sync workflow.
